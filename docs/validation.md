# Validation and measured results

Recorded on 2026-09-28–29 with Python 3.12.3, Pillow 11.3.0, Mido 1.3.3,
Playwright 1.55.0, and Chromium 140.0.7339.16, Linux x86-64 / glibc 2.39.
`requirements-dev.txt` pins the validation dependencies. Run
`.venv/bin/python scripts/verify.py` after provisioning them.

## Evidence

- 240 seeded cases (PRNG seed 20260928) include RGBA random cells, solid colors,
  gradients, complete transparency, uneven dimensions, multiple scales, and tempo
  endpoints. The oracle sums original pixels in separate code, independently
  composites them against black, and checks every region, RGB mean, brightness,
  pitch, velocity, tick and sample boundary. Fraction arithmetic independently
  checks time rounding. Every case is rendered twice and all six artifact byte
  strings are compared; original input bytes and hashes are checked unchanged.
- Mido independently parses all 240 exported MIDI files. Tests compare tempo,
  division, note-on/off ticks, pitch, velocity, event ordering, silent intervals,
  and final track duration with JSON.
- Analytical WAV fixtures check RIFF size, mono PCM parameters, frame count,
  first/last sample, peak bounds, exact silence, and frequency from zero crossings
  (within 0.5 Hz of the MIDI tuning target).
- Network-blocked Chromium checks initial pause, user-triggered playback, media
  clock progression and region timing, pause stability, seek, restart, ending,
  replay, note selection, arrow/Home/End keys, all five content downloads, and
  reopening the downloaded HTML. Hostile filename text remains text. No page
  errors, dialogs, or HTTP(S) requests are permitted by the test.
- Chromium's audio decoder is also given the actual embedded WAV; rate, length,
  and every decoded sample are compared against exported PCM with a one-integer-
  step tolerance (1/32768). An initial 1e-6 tolerance failed with an observed
  maximum difference of 1.4812e-5; the decoder's float normalization is not exactly
  the integer/32768 convention. This is a decoder check, not captured sound from
  a physical output device.
- Additional tests cover grayscale, palette transparency, EXIF orientation,
  CMYK JPEG, rejected bit depths/animation/formats, malformed data, input and
  output caps, duration/note boundaries, existing directories and symlinks,
  concurrent publication, simulated disk-write failure, KeyboardInterrupt, and
  an actual SIGTERM delivered during a controlled CLI write. Failed writes leave
  no destination or staging directory. Byte/pixel/output cap checks include
  lowered-limit injections; they do not claim exhaustive hostile-codec fuzzing.
- The installed check builds a wheel without a package index, installs into a
  temporary target, and executes its installed entry script outside the checkout
  using Python `-S`, with only the copied pinned Pillow dependency. It creates a
  complete six-file bundle. The test does not depend on the editable source path.
- Desktop (1200 px) and mobile (390 px) screenshots were visually inspected for
  layout. No human screen-reader or musical listening evaluation was performed.

`results/tests.log` is the actual verification output. The benchmark checker
requires all regenerated artifact sizes and SHA-256 values to match the reference
in `results/benchmark.json`; runtimes and memory can vary across executions.

## Limits of the evidence

No blinded listening, perceptual quality, musical usefulness, or comparison with
other sonification algorithms was measured. There is no claim of learned
cross-modal understanding, scientific auditory interpretation, or novelty.
Sine previews intentionally sound different from a piano MIDI player. Browser
checks validate media-clock behavior and decoded samples, not speaker latency or
physical audio output. Firefox, Safari, macOS, and Windows have not been run.
Floating-point/codec differences can affect byte identity outside the pinned
Linux environment. Atomic rename depends on filesystem support; abrupt SIGKILL
and power loss cannot guarantee cleanup or disk durability.

## Saved-score editing validation (2026-09-30)

The version 1 measurements and results above are historical and retained. The
editing milestone uses Python 3.12.3, Pillow 11.3.0, Mido 1.3.3, Playwright 1.55.0,
and Chromium 140.0.7339.16 on Linux x86-64 / glibc 2.39. Run the same single
verification command: `.venv/bin/python scripts/verify.py`.

The edit oracle runs **240 cases**, seed **20260930**, in addition to the original
240 mapping cases. It independently constructs expected events, uses rational
arithmetic for timing, parses MIDI through Mido, and inspects actual PCM frames.
Cases combine tempo endpoints and fractional sample boundaries, signed transpose,
velocity assignments, sparse mute/unmute maps, all-muted and all-zero-velocity
scores. All six exports are compared byte-for-byte across repeated generation.
Identity exports preserve original MIDI/WAV/PNG bytes. Sequential-edit checks cover
accumulating transposition, absolute assignments, preserved muted velocity,
explicit unmuting, stable IDs, parent fingerprints, and source-image deletion.
Targeted frequency fixtures measure ±12 and +24 semitone changes by zero crossings
(within 0.5 Hz), and check amplitude bounds and exact muted silence.

Import tests cover malformed schemas, unsupported versions, invalid integers and
booleans, unknown/duplicate fields and IDs, invalid ticks/sample positions, image
bounds and colors, missing/extra files, hash mismatches, invalid PNGs, symlinks,
FIFOs, traversal manifest names, oversized edits, and injected byte/pixel/note/
duration caps. Output caps are checked before calling the WAV renderer. Error
coverage includes existing output directories/symlinks, nested outputs, serialization
failure, simulated disk failure, KeyboardInterrupt, and actual CLI SIGTERM during
staging. Existing concurrent-publication tests are retained.

Network-blocked Chromium exercises edited playback, pause, seek, highlighting,
inspection of a muted note's stored velocity, zero-velocity rest labels,
arrow/Home/End keyboard navigation, ending/replay, all content downloads, reopening
the downloaded report, and independent browser decoding of the exported WAV.
Hostile imported filename text stays text; imported executable HTML is discarded.
The isolated installed check builds/installs without a package index, converts an
image, deletes that original image, edits its bundle, then imports the version 2
bundle again to unmute it through the installed `image-score-edit` entry point.

Two initial validation failures were resolved and are recorded here rather than
hidden: the first baseline run could not launch the absent pinned Chromium binary;
installing it allowed the unchanged baseline to pass. The first edited browser
run exposed sample-boundary highlighting at 90 BPM: Chromium's seek clock could
fall a fraction of a sample below a note start. The edited viewer now compares
nearest-sample clock positions, and the browser regression passes. The version 1
viewer remains byte-identical for historical reproducibility.
